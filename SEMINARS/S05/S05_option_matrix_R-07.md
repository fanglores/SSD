# S05 - R-07 MITM / подмена внешнего API (Spoofing)

## Контекст риска (из S04)

- **Risk-ID:** R-07 **Threat:** S (Spoofing)
- **DFD element/edge:** Edge: Service → External API (Outbound request, MITM)
- NFR link (ID): NFR-010
- **L×I (1-5):** L=3, I=5, Score=15
- **Ограничения/предпосылки:** Backend (FastAPI), REST интеграция с внешними API, корпоративный TLS CA, сценарии интеграции с Vendor-x, требования по HTTPS для всех external endpoints, возможны ограничения на внедрение mTLS (фактор сторонних сервисов), согласование сертификатов.

---

## Критерии и шкалы (1-5)

**Польза (чем больше - тем лучше, ↑):**

- **Security impact (↑):** насколько альтернатива снижает риск (предотвращает/обнаруживает/сдерживает).
- **Blast radius reduction (↑):** насколько сужает возможный ущерб (только один тенант/аккаунт/фича вместо всего сервиса).

**Стоимость/сложность (чем меньше - тем лучше, ↓):**

- **Complexity (↓):** сложность внедрения (код/конфиг/политики).
- **Time-to-mitigate (↓):** сколько времени до эффекта (в днях/спринтах).
- **Dependencies (↓):** внешние/внутренние зависимости (команды, провайдеры, миграции).

> Оценка **1-5**: 1 - минимально / 5 - максимально. Для «стоимостных» критериев **меньше - лучше**.

**Итоговые метрики (подсказка):**

- **Benefit = Security impact + Blast radius reduction**
- **Cost = Complexity + Time-to-mitigate + Dependencies**
- **Net = Benefit − Cost** _(чем больше, тем привлекательнее)_

## Решение (ADR candidate)

**Chosen alternative:** TLS + CA verification for outbound
**Почему:** Быстро даёт максимальный охват, реализуемо на большинстве внешних API, не требует сложного согласования.
**ADR candidate:** “Outbound TLS + CA for External API Calls”
**Связки:** Risk-ID R-07, NFR-ID NFR-010, DFD Edge: Service → External API

**Следующие шаги:**

1. Включить обязательную проверку CA для всех outbound external API calls.
2. Реализовать автоматическую проверку валидности сертификата перед отправкой запроса.
3. Протестировать сценарии интеграции с основными vendor-x и проверить отказоустойчивость при ошибках TLS.
4. Обновить документацию по новым требованиям к внешним API.
5. Добавить мониторинг попыток интеграции без корректной TLS/CA.
